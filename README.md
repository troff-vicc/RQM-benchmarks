# RMQ Benchmarks:

> **TL;DR.** Все меряют RMQ по времени *запроса*. В реальности ты строишь
> структуру один раз и гоняешь `q` запросов — **total time** (`build + q × query`)
> и есть то, что важно. Здесь измерены 5 структур на 3 режимах `q/n` —
> и точка crossover'а между ними.

## 📖 Readable versions

**Каждый алгоритм есть в двух видах.**

| | Где | Для чего |
|---|---|---|
| **Readable** | `readable/<name>.cpp` | Понять алгоритм + скопировать в свой проект |
| **Fast** | `include/rmq/<name>.hpp` | Бенчмарк: шаблоны, `std::size_t`, компаратор |

`readable/` — это **отдельные `.cpp`-файлы**, по 30–80 строк, в «учебниковом» стиле:

- без шаблонов, без `namespace`, без `size_t` — только `int` и `std::min`;
- комментарий-шапка: сложности, контракт `[l, r)`, идея;
- **`main()` с тремя примерами** — можно скомпилировать и запустить сразу:

  ```bash
  g++ -std=c++2b readable/sparse_table.cpp -o /tmp/st && /tmp/st
  ```

## Key findings

> *Заполнить после финальных прогонов, но скелет такой:*

- **При `q ≫ n`** (много запросов на маленьком массиве) побеждает `SparseTable`:
  `O(1)` на запрос компенсирует `O(n log n)` построение.
- **При `q ≪ n`** (мало запросов на большом массиве) побеждает `SegmentTree`:
  `O(n)` построение важнее `O(log n)` запроса.
- **Точка crossover'а** — при `q/n ≈ X` (заполнить после серии прогонов).
  Это главный график статьи: `docs/results_crossover.png`.
- **SqrtTree** — конкурент `SparseTable` при `q ≈ n`, проигрывает `~1.5×`
  на больших `n`, но сравним по времени построения. **`O(n log log n)` памяти
  на практике не даёт выигрыша** из-за константы `between` (честный результат).
- **Pointer-based структуры** (Treap, SplayTree) проигрывают массивам в
  **10–50×** на больших `n`. Не из-за асимптотики — из-за cache miss'ов
  (≈80 на запрос против ≈2 у SparseTable).

## Algorithms

| Structure | Build | Query | Memory | Notes |
|---|---|---|---|---|
| `SparseTable` | `O(n log n)` | `O(1)` | `O(n log n)` | Эталон `O(1)` на запрос |
| `SegmentTree` | `O(n)` | `O(log n)` | `O(n)` | Эталон `O(n)` построения |
| `SqrtTree` | `O(n log log n)` | `O(1)` | `O(n log log n)` | Константы съедают выигрыш |
| `Treap` | `O(n)` expected | `O(log n)` expected | `O(n)` | Pointer-based, seed рандомизирован |
| `SplayTree` | `O(n)` | `O(log n)` amortized | `O(n)` | Amortized, `query` мутирует |

Все структуры: **0-based индексация**, **полуинтервалы `[l, r)`**,
контракт `0 <= l < r <= n`. Поддержка `min` (default) и `max`
(через `std::greater<T>`) — параметр шаблона `Cmp`.
